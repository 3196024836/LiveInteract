## 分档与可用性分别判断

- Boss沿用原作身份与已有 `IsBoss`；两者必须一致。高生命非Boss不会自动改成Boss。
- 非Boss以原作1×生命参照为初筛：60及以上列强怪，低于60列弱怪。持盾战术、旋转切割、悬丝结构、高阶战士等少量特例逐项列强怪，原因写在每条记录中。这是本工具的玩法分档，不是游戏官方等级。
- 生命参照优先使用 `artifacts/pool-monsters.json` 的预制体生命字段；其余读取 `artifacts/audit-friendly-0.8.2/friendly-matrix-2014.jsonl` 对应 `RootId` 的初始生命。后者由 `matrix-2014.py` 以 `power=1` 生成，只取数值，不读取通过/失败结论。历史副本生命不等于重新提取全部原始资产；CSV逐项标明来源。
- 特例参考 `artifacts/ZH_Journal.decoded.xml` 的原作图鉴描述与预制体变体身份。沙噬虫是补生命的特殊单位，副本30生命不作为原生耐久证据，暂归弱怪；炽焰之父仍按Boss身份归类。可继续按新增原作证据修订单项分类。
- `CanFight` 只表达原作有无攻击。滑叶虫、生质飞籽、惊叫虫、沙行虫均为false：保留档案，但不出现在可选效果中，准确名/别名/效果ID解析、旧生成入口和转友军入口都明确拒绝。不把AI失败或场景依赖改写成“无攻击”。
- `RandomEligible` 继续沿用本次接手的0.8.7限制，没有因分类解除。分类不代表主动战斗或跨场景随行验收通过。稳定性问题只写召唤资格与排除原因，不更改 `CanFight`；生质蠕虫按固定地形排除；赛斯的旧场景Dormant/未见本体属于待修、待验，不是本轮永久排除。

## 新旧随机池

| pool值 | 内容 |
| --- | --- |
| `weak` | 可战斗且在当前召唤白名单的弱怪，不使用旧随机标记 |
| `strongBoss` | 可战斗且在当前召唤白名单的强怪与Boss，不使用旧随机标记 |
| `ordinary` | 旧版普通池：可随机的弱怪与强怪，不含Boss |
| `all` | 旧版全池：可随机的弱怪、强怪与Boss |

新 `weak`/`strongBoss` 检查 `CanFight`、`SummonEligible` 与Tier；旧 `ordinary`/`all` 及bool、Boss/FreeAlly另检查 `RandomEligible`。分类CSV的“随机资格”列保留旧字段原值，仅表示legacy限制。空池明确报错，不回退其他单位。接手时旧随机资格覆盖的战斗档案为26项（弱怪13、强怪10、Boss3）；新池与旧池的资格分开，不能据新池开放改写这26项历史范围。相同目录与执行单位ID按效果ID排序后稳定抽签，加载重试不重新抽；未知池报错，不回退。

兼容接口 `RandomMonster(string executionId, bool includeBoss)` 保留：false→ordinary，true→all。新接口为 `RandomMonster(string executionId, string pool)`。

旧规则未写pool时，动作目录仍按ordinary处理；编辑器新选“随机召唤”显式写weak。读取或编辑现有规则不会把ordinary/all和自定义倍率自动迁移。

## 旧随机资格的来源

焦油螨 `spawn.bone-spitter` 与燧石飞工 `spawn.dock-flyer` 的 `RandomEligible=false` 是历史新增场景单位的默认隔离，不是原作无攻击或逐只永久排除结论。原始生成脚本 `artifacts/audit-0.8/build_catalog.py:28` 对新增条目统一写false，`:32` 明确记录 `UnverifiedAddedUnitsExcludedFromGiftRandomPool=True`；`catalog-coverage.json:7-8,278` 对应当时27个独立预制体、203个新增场景对象及该限制。两项都不在旧27项独立目录中，其当前来源分别为 `bone_east_lavachallenge`、`bone_09`。该历史批次统计不等于当前234项统计。

新 `weak`/`strongBoss` 仅按 `CanFight + SummonEligible + Tier` 选取；旧 `ordinary`/`all`、bool重载及 `Boss`/`FreeAlly` 仍额外要求 `RandomEligible`。该字段仅保留历史随机限制，归档false标记不改；焦油螨与码头飞工进入新弱怪池，不进入旧池。 这是已实现的新旧语义分离；同一执行ID的选择仍确定，空池仍明确拒绝，无全目录回退。当前六项为冻结候选，完整发布验收尚未完成。

## 默认方案

四件礼物保留原ID、触发、数量与阵营：小心心→2只弱怪友军，玫瑰→1只弱怪敌军，棒棒糖→2只强怪/Boss友军，给到夯→1只强怪/Boss敌军；全部power=1。远程小弟暂定码头飞工、远程小怪暂定焦油螨、小怪保留颅潜虫；机械小弟不变。更换内置方案仍须主播主动操作，不覆盖已有自定义规则。这三个及其他候选已有QA7核心与持久化等局部证据，QA12/QA14地形修复由主线回报；生产白名单冻结六项，最终统一矩阵和长测仍待主线完成。

规则预览与海报分别显示“池”和非1×倍率，旧版池有显式标记。目录分类、默认配置与单元测试不能替代本轮实机攻击、随行和性能验收。
