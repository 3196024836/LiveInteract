# 0.8.1 热更与代码复核结果

日期：2026-10-21。本轮仅本地修复、构建、隔离测试；未发布GitHub，未上调公开更新清单。

## 已修复

- 发布ZIP带外层文件夹时主程序被放错位置：预检后规范化到唯一主程序根目录。平铺/单层包装都支持。
- 固定版本暂存路径会先删旧目录，版本号还能变成路径：严格版本格式、本次独立目录、拒绝不安全路径/链接/重复名/越限包，不破坏旧暂存。
- 下载可无校验、取消可残留半包、同版本并行下载互相覆盖：强制发布大小与SHA-256，逐跳验证URL，每次唯一文件，失败清理。
- 收到响应头后正文卡住不受HttpClient原超时约束：整段清单/下载/校验共用截止令牌，保留原API；两项真实HTTP红绿用例确认超时生效、报出原因、清理半包（body-timeout-red.trx）。
- 旧进程等待超时仍继续覆盖：超时取消，不终止旧程序，不再重复启动。
- 中途文件占用会留下混合版本：完整备份与清单先落盘，逐文件原子替换；异常反向回滚、移除本次新增文件；回滚失败禁止自动重启。
- 更新混入用户配置/数据库，失败又把现场清掉：只安装软件载荷；保护当前规则、设置、数据库、登录环境、固定浏览器；只在成功且已启动后清理本次暂存。
- 更新会直接Shutdown打断直播：接入窗口/互动开关/游戏/维护/未处理帧/未评估输入/未完成任务任一忙碌则不重启；走正常异步关闭。
- 额外WPF故障注入发现SavePreferences吞掉保存异常、仍然退出：更新与关闭显式要求保存成功，失败保留窗口/服务并显示原因，其余既有调用方式保留。
- 配置与偏好固定.tmp并发冲突：统一AtomicFile，同目录唯一临时文件、落盘、串行原子提交。Windows实测证明仅换唯一临时文件仍会发生重命名Access denied，串行提交后80次并发保存通过。
- 存档恢复先挪走当前存档才写恢复信息：改为先写好恢复信息，再进入受保护的移动/恢复步骤。
- 三套打包脚本版本和依赖不一致：共用new-distribution.ps1，版本取项目属性，四个Mod依赖一致，强制非QA构建，保留旧包，精简包去掉SDK XML。
- 发布脚本会全仓git add -A、同版本clobber：默认仅本地准备；显式-Publish且工作区已提交才可发布，只提交更新清单，不覆盖已存在版本资产。完整/精简更新不再静默混用。

## 重构边界

更新分为UpdateService（清单/下载）、UpdatePackage（版本/文件/解包边界）、UpdateInstaller（替换/备份/回滚）、MainWindow.Updates（提示/生命周期）。原UpdateApplier.Apply入口保留。AtomicFile复用于配置、偏好和更新回执。测试仍使用原UiSmoke/QueueUiSmoke/UpdateSmoke入口，回归脚本明确选择当前包，不按名字排序选错旧包。

全仓扫描覆盖120个源码/配置/脚本文件，其中89个C#文件，清单与JSON检查见artifacts/audit-update-0.8.1/code-inventory-final.json。重点人工复核接入→去重→账本→队列→执行→回执、持久化、维护与发布。GameActions/原作战斗适配仍较大且有未完成AI用例，本次不因文件长就重写该共享状态机，避免破坏已有实机证据。
