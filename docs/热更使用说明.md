# 程序更新与失败恢复

在“画面与设置”点击“检查更新”，或保留启动自动检查。发现版本后，确认才下载和重启，不会自动替换游戏中已加载的 DLL。

## 更新前

关闭直播接入窗口、暂停新触发、处理完待办队列并正常退出游戏。有未解析帧、未评估事件或未完成任务时，程序拒绝重启更新；不会为了更新清空礼物。

更新后点击“一键准备游戏”部署新 Mod，然后重开游戏。当前 rules.json、settings.json、账本、登录目录和游戏存档不由更新包覆盖；profiles 中的原厂默认模板随程序更新，当前已应用规则不自动替换。

## 失败时

清单读取整体限时15秒，下载与校验整体限时10分钟，正文卡住同样会超时并显示原因。下载必须与发布大小及 SHA-256 一致；取消、断流、篡改不会留下可安装半包。解包拒绝不安全路径/链接，支持平铺 ZIP 和单层发布文件夹。

替换前会备份所有将覆盖的文件；文件被占用等异常会回滚，新增的文件也会撤回。回滚失败时禁止自动启动混合版本。程序目录 update-result.json 和 update-error.txt 记录结果；重开工具后控制台会显示失败原因。失败的暂存包和 backup-* 保留在用户数据目录 update 下，备份中的 transaction.json 记录安装位置和原文件清单。

断电或强制结束更新辅助进程不是已验收的自动恢复路径。此时不要继续覆盖，保留 update 目录及原程序，在确认所有工具实例退出后按 transaction.json 和 files 备份恢复；不会自动重放结果未知的礼物。

## 精简版与完整版

精简包优先复用兼容运行时；缺少 .NET 时由内部引导安装到本工具的私有目录，缺少 WebView2 时在内部下载并校验微软安装器，不需要跳转网页手动准备。已有固定 WebView2 浏览器仍可复用。首次准备需要联网。旧完整版更新必须有匹配的 FullPackage 自带运行时载荷；发布方只提供精简包时会明确拒绝降级，原程序保持可用。

## 维护发布

三个打包入口共用 scripts/new-distribution.ps1；版本来自 Directory.Build.props，四个 Mod 依赖一致，正式 Mod 总是排除 QA。package-slim.ps1 是精简入口；package.ps1/package-full.ps1 保留完整包调用方式。默认输出 preview 包并保留旧包，-Channel '' 用于正式版本名称。

scripts/publish-release.ps1 默认只做本地准备，不上传、不提交、不推送。明确授权发布后使用 -Publish，要求源码已提交且工作区干净；只提交 update/latest.json，不覆盖既有版本资产。可用 -FullUpdateZip 指定匹配的完整版更新载荷（不重复打包已保留的固定 WebView2）。当前版本本次交付本地实机测试包，未自动发布到GitHub或修改公开更新源；只有完成公开发布后，其他机器的“检查更新”才会发现该版本。
